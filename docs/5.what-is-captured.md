Each part can be switched off with its `enable…` option, see [Configuration](./2.configuration.md).

## Screenshot

- Taken in the browser with `modern-screenshot`, no server or Chrome needed.
- The visible area, including the scroll position.
- The background follows light or dark mode.
- Attached to the Linear issue.

## User journey

The last actions before the report, shown as a timeline:

- Clicks with element information
- Page changes and URL changes
- Focus, blur and submit of forms
- Important key presses
- JavaScript errors

## Network requests

`fetch` and XHR requests with method, URL, status, duration, error details, request and response headers, and the
request and response bodies, each cut at 1000 characters. Requests for static files (`.css`, `.js`, images, fonts)
are skipped.

## Console output

Console messages up to `maxConsoleLogs`. CSS styles of `%c` output are removed.

## Browser details

Browser name and version, user agent, operating system, viewport and screen size, performance figures, language and
time zone.

## What is filtered

| Data | Filtered |
|---|---|
| Headers `Authorization`, `Cookie`, `Set-Cookie`, `X-API-Key`, `API-Key`, `Token` (request and response) | value replaced with `[FILTERED]` |
| Query parameters `token`, `apikey`, `api_key`, `secret`, `password`, `pwd` in URLs of the user journey | replaced with `[FILTERED]` |
| Values typed into fields | not recorded unless `captureInputValues: true`, and never for password, token and similar fields |

Not filtered: the **request and response bodies** and the **URLs of network requests**. A sign-in request, for
example, goes into the report with its body, and an answer that carries a token with that token. Keep that in mind for apps that send credentials or personal data in request bodies, and switch
`enableNetworkRequests` off where that is not acceptable. Angular apps on `@lenne.tech/ng-base/bug` never record the
bodies of auth endpoints.
