## How a report becomes an issue

The browser sends the report to the app's own server (`endpoint`, default `/_bug-lt/report`). The server handler
creates the issue through the Linear API:

- **Team** by name or key, not by id.
- **Project** by name, optional.
- **Screenshot** as an attachment of the issue.
- **Description** with the report, the steps, the user journey, network requests, console output and browser
  details.

The API key never reaches the browser.

## Labels

Each report type gets a label in the team. A missing label is created:

| Type | Label | Color |
|---|---|---|
| Bug | `bug` | red |
| Feature | `feature` | blue |
| Enhancement | `enhancement` | green |
| Other | `other` | purple |

## API key

Create a personal API key in Linear under Settings → API. It needs write access, and it acts for the whole
workspace with the rights of the person who created it. Store it as a secret on every stage, never in the repository or
the build.

## Deployed stages

`process.env` in `nuxt.config.ts` is read at **build time**. A container build (Docker, CI) usually does not have the
secrets, they are injected at **runtime**. The module then ends up in the image without credentials, and every report
answers `500 "Linear API is not configured. Please set linearApiKey."`, but only when somebody reports a bug. Until
then everything looks healthy.

So on deployed stages the credentials are not set in `nuxt.config.ts` but as environment variables of the stage. Nitro
maps them onto `runtimeConfig.bugLt`:

```bash
# set on the stage, not in the build
NUXT_BUG_LT_LINEAR_API_KEY=lin_api_...
NUXT_BUG_LT_LINEAR_TEAM_NAME=<team name or key>
NUXT_BUG_LT_LINEAR_PROJECT_NAME=<project name>
```

The `bug` block in `nuxt.config.ts` then has no `linearApiKey` and so on; the values come from `runtimeConfig.bugLt`
per request.

Two traps that cost time in practice:

- **`enabled` is a build-time flag.** `enabled: process.env.SOMETHING !== 'production'` is evaluated against an empty
  variable in a container build and is always `true`. To switch the button per stage, use
  `NUXT_PUBLIC_BUG_LT_AUTO_SHOW=false` at runtime, which works without a rebuild.
- **Old variable names stay silent.** A project that moves from `NUXT_LINEAR_*` to `NUXT_BUG_LT_*` has to do so on
  **every** stage. A stage with the old names is read by nobody, reports nothing, and answers the 500 above.
